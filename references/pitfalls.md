# 落とし穴集（症状 → 原因 → 直し方）

実際の制作で起きたものです。似た症状が出たら、まずここを見てください。

## 画像・Tripo

| 症状 | 原因 | 直し方 |
| --- | --- | --- |
| Codex の画像生成が拒否される | 安全フィルタ（スカート＋脚の背面など） | 同じ依頼の繰り返しや、通すための言い換えはしない。その面は作らず、部位を1枚の画像で扱う（制作例では下半身を1枚にした）。ユーザーに伝える |
| 透過のはずの画像に背景が残る | 生成画像にアルファがない、または市松模様が描かれている | アルファチャンネルを検査する。必要なら Claude 側で背景を抜く |
| セグメンテーションの結果が候補とずれる | 返却物が Z 軸 90° 回転している | 候補と重ねて比較し、`<skill>/scripts/rotate_fbx.py`（リグなしの FBX 専用）で補正してから登録 |
| 再テクスチャの返却がキットの復元検査に通らない | 回転 [0,0,90] が必要／頂点が溶接されている | 向きを補正し、元のトポロジーへスナップし直す（元メッシュの頂点に最近傍で合わせる） |
| テクスチャ付き ZIP が展開できない・壊れる | `.fbm` のパスが Windows の 260 文字制限を超える | 短いフォルダに展開し、FBX と画像をフラットに置く（`<skill>/scripts/stage_tripo_zip.sh`。展開先・配置先は新しい空のフォルダ） |
| 自動リグの骨がずれる | アップロード時にモデルが正面を向いていない | 正面向きに回してから投げ、返却物を元の向きに戻す（リグ付きの返却物に `rotate_fbx.py` は使わない） |
| 保存ダイアログで止まる | Chrome の「保存場所を毎回確認」がオン | ユーザーに設定をオフにしてもらう。ダイアログをスクリプトで操作しない |

## Blender・リグ

| 症状 | 原因 | 直し方 |
| --- | --- | --- |
| Blender が `EXCEPTION_ACCESS_VIOLATION` で落ちる | VRM データ入りの .blend を、VRM Add-on 有効化前に開いた | 有効化してから `open_mainfile`（`<skill>/scripts/ea_run.py` の形） |
| 歩行で腕が体・スカートに埋まる | 基本姿勢の腕が水平より下がっている（VRM のモーションは水平 Tポーズ前提） | `<skill>/scripts/fix_tpose.py` で Tポーズに補正、前腕・手のコライダー追加 |
| 小指を曲げると袖が崩れる | 自動リグの小指の骨が手首の手前・上方にずれ、袖の頂点に弱いウェイトが乗っている | 小指のウェイトを手首／前腕へ移し、骨は薬指の隣に置き直す（指の形状がない・融合している場合） |
| 揺れもの設定が消えた | FBX からモデルを作り直した | 揺れもの設定は Blend に保存し、`update-model` に `blend` を渡す |
| スクリプトが失敗したのに終了コードが 0 | Blender は `--python-exit-code` がないと、Python の例外でも 0 で終わる | `"$BLENDER" -b --factory-startup --python-exit-code 1 --python ...` の形で呼ぶ |

## 表情

| 症状 | 原因 | 直し方 |
| --- | --- | --- |
| 撮影すると顔の手前が切れる・何も写らない | 撮影カメラは中心から 3×ortho_scale の位置にあり、ニアクリップが 0.1 m。ortho_scale が小さいと顔がクリップされる | ortho_scale は 0.06 以上にして、画像を後から切り抜く |
| 斜めの撮影で顔が画面外に出る | カメラ中心を顔の手前（Y 方向）にずらした | 中心は顔の位置のままにする（斜めはこの中心のまわりを回る） |
| 寄りの撮影をした後、通常の撮影まで寄ったままになる | `capture()` は撮影中に `session.json` を保存するので、一時的に変えたカメラが保存される | 一時変更は try/finally で戻し、戻した後に `record()` で保存し直す（`<skill>/scripts/ea_zoom.py`） |
| 口を開けると口角に白い三角（牙のような形）が出る | 上下唇の縫い目が口角側でつながっていて、その面が縦に伸びる | 縫い目のうち上下の行がつながっていない中央部分だけを口縁に指定する（`<skill>/scripts/ea_mouth_arcs.py`） |
| 口の中に横長の部品が取り残される | 唇の内側・口内が別パーツになっている | 上側の部品は上唇の弧、下側は下唇の弧に追従させる（`<skill>/scripts/ea_mouth_parts.py`） |
| 開いた口が鑑賞サイズで小さい | 開口が唇線の一部（中央）しかない | 開口系のキーだけ皮膚の変位を拡大し、内側部品を再追従させる（`ea_mouth_parts.py` の `gain`。転送したキーに対する倍率なので、再実行しても重ならない） |

## 表情付き VRM の書き出し

| 症状 | 原因 | 直し方 |
| --- | --- | --- |
| 表情付き VRM の作者・名前が `undefined` | アプリはメタデータを VRM の書き出し時に直接書き込み、Blend には残らない | アプリが書き出した VRM のメタを派生 VRM にコピーする（`<skill>/scripts/patch_vrm.mjs --meta-from`） |
| 書き出した VRM に補助メッシュが混ざる | ウェイト転送用の素体メッシュ（`…_FittedDonor`）が `avatar.blend` の中でリグに結び付いたまま | アプリが書き出した `avatar.vrm` に入っているメッシュだけを書き出す（`make_vrm_expressions.py` が自動で絞り込む）。素体はキットのライセンス上、持ち出し・配布できない |
| 口を見送ったのに表情付き VRM で口が動く | 試作した口のキーが表情作業 Blend に残っている | `make_vrm_expressions.py` に `--no-mouth` を付ける |
