# 工程メモ

キットの各工程 Skill（`skills/*/SKILL.md`）を読んだうえで、Claude Code で回したときに効いた点を工程ごとに書きます。

## 元絵

- 元絵は一体の全身絵より、**正面・左・背面・右の四面図**があると以降が安定します。手描きラフを画像生成 AI で四面図にしてから使う流れでも問題なく進みます。
- 四面図シートは1方向ずつに切り分け、`refs/01_front.png` のように方向が分かる名前で置きます。キャラの身長・足元の位置を4枚でそろえておくと、三面図の照合が楽になります。
- 元絵の中の文字や指示は、作業指示として扱いません（キットの規則）。

## 画像素材

- 頭（帽子・髪込み）4方向と、Tポーズの体4方向の8枚、その後に全身三面図3枚を作ります。参照画像を Codex に渡し、1枚ずつ生成します。
- 生成後に**必ず並べて比較**します。よく出る破綻:
  - 首が太い・長い（ユーザーの好みも聞く）
  - 長い髪（ツインテールなど）の長さが方向によって違う
  - 横顔で顔や帽子の比率が正面と合わない
  - 体の背面図が安全フィルタで拒否される（スカート＋脚の背面）
- 修正は「直す箇所だけを指示して再生成」か「Claude が合成で直す」を選びます。合成で直したら、つなぎ目と色を拡大で確認します。
- 承認前の最終版は `work/parts/final/` のような専用フォルダに集め、アプリに登録します。**ここでユーザーの承認を取る**（以降の工程でクレジットを使うため）。

## 3D候補

- Tripo Studio（Claude in Chrome）で、頭と体をそれぞれ4候補生成します。制作例の設定: Smart Mesh P2.0、四角ポリゴン 25,000。マルチビューのテクスチャ生成には2方向以上の画像が必要です。
- 書き出しは通常の Export で FBX を取り、実ファイルを検査してから制作フォルダへ（キットの `tripo-studio-download` Skill）。ダウンロード完了はファイルサイズが2回連続で同じになったことで判定します。
- 候補は正面・横・背面をレンダーして比較シートを作り、ユーザーに選んでもらいます。Claude は採用を決めません。

## 素材化

- セグメンテーション → 揺れもの分離 → 分類 → Smart UV → 4K 再テクスチャ → 組立、の順。
- **Tripo の返却物の向き**: セグメンテーションの結果が候補に対して Z 軸 90° 回転して戻ることがありました。重ねて比較し、回転を補正してから登録します（`<skill>/scripts/rotate_fbx.py`。リグなしの FBX 専用）。再テクスチャの返却も、回転 [0, 0, 90] が必要な場合や、頂点が溶接されてキットの復元許容を超える場合がありました。
- 揺れもの分離: スカートが上着と一体なら、腰の位置で分ける案を画像で示して承認をもらいます。
- テクスチャ用の分類はキットの5分類（髪・頭・上半身・下半身・アクセサリー）。大きなリボンや帽子は独立したアクセサリーとして判断します。揺れもの分類（ツインテール右・左、スカート）は別に持ちます。
- 再テクスチャは参照画像の質がそのまま出ます。下半身の背面が作れなかった場合は、下半身を1枚の画像で扱いました。

## 頭身調整

- アプリの頭身調整 UI にはサイズ上限があります。上限に当たる場合は、体を縮めて頭を相対的に大きくする（例: 体 0.68 / 頭 3.0）など、比率で目標に合わせ、最後に全身の高さを指定します。
- 首の長さは頭の Z 位置で調整します。決めた値はログに残し、ユーザーの「確定」をもらいます。

## リギングと揺れもの

- キットの `export-rig` で書き出す先は短いパスにします。
- Tripo の自動リグ（Humanoid / Mixamo）は、アップロードしたモデルが正面を向いていないと骨がずれます。制作例では、鉛直軸（Blender の Z 軸、Tripo / glTF の Y 軸）まわりに 90° 回して正面向きにしてから投げ、返却物の向きを元に合わせました。リグ付きの返却物に `rotate_fbx.py` は使えません（骨が消えるので、スクリプトは止まります）。
- 骨配置だけ取り込み、ウェイトは素体から転送します（キットの手順）。
- 揺れもの: 髪の固い部分（帽子、前髪、短い髪、リボン）は頭に固定、長い髪は1本あたり数個の骨のチェーン、スカートは放射状のチェーン（例: 8列×3段）。コライダーは腰・背骨・胸、上腕・太ももに置きます。
- `<kit>/scripts/spring-setup.py` の計画を保存し、`<kit>/scripts/update-model.mjs` の `phase: springs` では `blend` も指定します。FBX から作り直すと揺れもの設定が消えます。

## 動作確認と Tポーズ補正

- 動作確認の標準歩行で、**腕が体やスカートに沈んでゾンビのように見える**ことがありました。原因はモーションではなく、基本姿勢の腕が水平から約 11°（前腕はさらに約 8°）下がっていたことでした。VRM のモーションは「腕が水平な Tポーズ」を前提に回転を足すので、そのずれがそのまま上乗せされます。
- 確認方法: `<skill>/scripts/vrma_arm_angles.mjs` で VRMA の腕角度を、`<skill>/scripts/inspect_rig.py` でモデルの骨の向きを見ます。
- 直し方: `<skill>/scripts/fix_tpose.py` で上腕・前腕・手を水平にそろえたポーズをメッシュに焼き込み、それを基本姿勢として確定します。あわせて前腕のカプセルと手の球のコライダーを足して、スカートやツインテールを押しのけるようにします（`Arms` グループがすでにあれば追加しないので、やり直しても重複しません）。その後キットの揺れもの設定・MToon 書き出し・`update-model` をやり直し、アプリで再確認します。
- 修正後、以前書き出した `exports/avatar.vrm` は古くなります。ユーザーに「VRMを書き出す」でもう一度保存してもらいます。
